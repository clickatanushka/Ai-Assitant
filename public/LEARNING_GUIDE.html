Audit Assistant — Project Learning Guide

A short, practical tour of how your document Q&A app is built — what each file does, how a question turns into an answer, and how to change things yourself.

1. The big picture: what it does

You give it 82 German audit PDFs. You ask a question in English. It finds the right document, then writes an answer in both English and German with the exact page it came from.

It is built from three kinds of pieces, each with one job:

PieceFileIts jobHouse analogy
Backendserver.pyThe brain — reads PDFs, searches, talks to the AI, serves pages.The engine room
Frontendindex.htmlThe page you type your question into and read the answer on.The reception desk
Search dataindex.json + embeddings.npyThe pre-chewed documents the search reads (built once).The filing cabinet

3. How ONE question is answered (the worked example)

This is the most important idea: a single question flows through five steps inside server.py. Let's follow the question "msl".

your question → 1 expand → 2 translate → 3 embed & search → 4 ask Gemini → answer + sources

Step 1 — Expand short queries (so the search understands them)

"msl" is just 3 letters. The AI expands it into real words using general knowledge — not from your documents. The result is cached, so the same question always gives the same answer.

Step 2 — Translate to German (for the title match)

The documents are German. We translate the query to German (free Google Translate) so we can also match document titles.

code · translate_to_german()
def translate_to_german(text):
    return GoogleTranslator(source='en', target='de').translate(text)

Step 3 — Embed & search (the heart of it)

Every chunk of every PDF was turned into a list of numbers (an "embedding") that captures its meaning. We do the same to the query, then find the chunks whose numbers are closest. A small bonus is added when a distinctive German word appears in the filename.

5. The settings you can change (top of server.py)

PDF_DIR        = "./pdfs"          # where the documents live
EMB_MODEL_NAME = "BAAI/bge-m3"     # the search model (understands meaning)

PORT           = 8000             # open http://localhost:8000

6. The one thing you must set up

Your Gemini API key. The file api_key.txt holds one line — your key from aistudio.google.com. Billing must be enabled on it (the free tier is only 20 questions/day). Without a valid key, the search still finds documents, but no answer can be written.

7. The dashboards (bonus pages)

Three standalone pages, linked by the tab bar at the top, built with Chart.js:

  • dashboard.html — Operations & Quality (bars, pies, histograms, 10-year trends)
  • operations2.html — ISO 9001 (the original monitoring charts)
  • sales.html — Sales & Marketing (sample data)

Each time-series chart shows Actual bars + a line through the peaks + a dashed Target line, over 10 years (missing years filled with 0).

8. Try it yourself (safe little experiments)

Change this……and this happens
Start the server: ./venv/bin/python server.pyOpen localhost:8000 and ask a question
In server.py, change BOOST_CAP to 0.25Title matches count more (riskier — more noise)
Drop a new PDF into pdfs/ → click Re-indexThe new document becomes searchable
In a dashboard, edit a number in the data arraysThat bar/line updates on refresh
Golden rule: change one small thing, save the file, refresh the browser (or restart the server), and look. That tight loop is how you learn fastest — and you can always undo.
